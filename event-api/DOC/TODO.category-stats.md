**Название задачи**

- **Implement Analytics API:** `GET /v1/api/analytics/category-stats`

**Краткое описание**

- Реализовать endpoint `GET /v1/api/analytics/category-stats` для выдачи статистики по категориям (количество/суммы/средние значения и итоги) за указанный период с поддержкой фильтров, пагинации и авторизации.

**Требования и контракт (API spec)**

- **URL:** `GET /v1/api/analytics/category-stats`
- **Auth:** Bearer token (JWT) в заголовке `Authorization: Bearer <token>`. Только пользователи с ролью `analytics` или `admin` могут запрашивать данные.
- **Query params:**
  - `from` (optional, ISO8601 date): начало периода, пример `2025-11-01T00:00:00Z`. По умолчанию — 30 дней назад.
  - `to` (optional, ISO8601 date): конец периода, пример `2025-11-29T23:59:59Z`. По умолчанию — now.
  - `timezone` (optional): смещение/идентификатор временной зоны, по умолчанию `UTC`.
  - `metrics` (optional): CSV метрик: `count,sum,avg` (по умолчанию `count`).
  - `categoryIds` (optional): CSV идентификаторов категорий для фильтра.
  - `groupBy` (optional): как группировать — `category` (по умолчанию), `category,subCategory`.
  - `limit` (optional, int): число категорий в ответе (по умолчанию 100, max 1000).
  - `offset` (optional, int): смещение для пагинации.
  - `sort` (optional): поле для сортировки, например `count:desc` или `sum:asc`.
- **Response (200):**
  - `data`: массив объектов
    - `categoryId`: string|int
    - `categoryName`: string
    - `metrics`: object — ключи указанных метрик (`count`, `sum`, `avg`) со значениями
  - `totals`: object — агрегированные метрики по всем подходящим категориям
  - `meta`: объект с `limit`, `offset`, `total` (общее число категорий под фильтром), `from`, `to`
- **Errors:**
  - `401` — unauthorized
  - `403` — forbidden (недостаточно прав)
  - `400` — bad request (некорректные параметры)
  - `429` — rate limit
  - `500` — internal error

**Примеры**

- Curl:
  - curl example:
    ```
    curl -G "http://localhost:8080/v1/api/analytics/category-stats" \
      -H "Authorization: Bearer <token>" \
      --data-urlencode "from=2025-11-01T00:00:00Z" \
      --data-urlencode "to=2025-11-29T23:59:59Z" \
      --data-urlencode "metrics=count,sum" \
      --data-urlencode "limit=50" \
      --data-urlencode "sort=sum:desc"
    ```
- Пример ответа (JSON):
  ```
  {
    "data": [
      { "categoryId": 1, "categoryName": "Music", "metrics": { "count": 120, "sum": 2400 } },
      { "categoryId": 2, "categoryName": "Tech", "metrics": { "count": 90, "sum": 1800 } }
    ],
    "totals": { "count": 210, "sum": 4200 },
    "meta": { "limit": 50, "offset": 0, "total": 12, "from": "2025-11-01T00:00:00Z", "to": "2025-11-29T23:59:59Z" }
  }
  ```

**Технические детали реализации**

- **Layering:** роут → контроллер → service → repository/DAO.
- **Запросы к БД:**
  - Использовать агрегации SQL (GROUP BY category_id) с индексами на `event_date`, `category_id` и полях, участвующих в фильтрах.
  - Если данные в OLTP быстрорастут, предусмотреть аналитический материализованный view или использование OLAP-куба.
- **Оптимизация:**
  - Ограничение диапазона дат (max 1 год) или отклонять слишком большие диапазоны.
  - Кэширование результатов по комбинации параметров на 1–5 минут (Redis).
  - Лимит `limit` по умолчанию и max.
- **Валидация:**
  - Проверять правильность ISO дат и `from <= to`.
  - Ограничивать `limit` и `offset`.
  - Проверять, что `metrics` содержит только разрешённые значения.
- **Безопасность:**
  - Проверка прав пользователя.
  - Rate limiting (per-user/IP).
  - Логирование запросов с ID запроса для трассировки (request-id).
- **Тесты:**
  - Unit-тесты для сервиса/валидатора.
  - Интеграционные тесты, имитирующие БД (fixtures) — проверить агрегации, фильтры, пагинацию и ошибки.
- **Документация:**
  - Добавить в OpenAPI/Swagger с примерами запросов и ответов.
  - Обновить `DOCS/API_INTEGRATION.md` или аналогичный раздел.
