# Discovery Filters

[← Вернуться к документации](./INDEX.md) | [Техническая документация движка](../Reference/DISCOVERY_ENGINE.md)

## Обзор

Discovery API поддерживает фильтрацию событий при получении следующего события в очереди. Фильтры позволяют пользователям видеть только те события, которые соответствуют их предпочтениям.

## Endpoint

```
GET /v1/api/discovery/next
```

## Параметры фильтрации

| Параметр     | Тип    | Описание                              | Пример                 |
| ------------ | ------ | ------------------------------------- | ---------------------- |
| `types`      | string | Типы событий через запятую            | `Конференция,Воркшоп`  |
| `priceTypes` | string | Типы цен через запятую                | `free,paid,donation`   |
| `places`     | string | Места проведения (поиск по подстроке) | `Коворкинг,Офис`       |
| `dateFrom`   | string | Начало диапазона дат (RFC3339)        | `2025-01-01T00:00:00Z` |
| `dateTo`     | string | Конец диапазона дат (RFC3339)         | `2025-12-31T23:59:59Z` |

## Примеры использования

### Фильтр по типу события

```bash
curl -X GET "http://localhost:8080/v1/api/discovery/next?types=Конференция" \
  -H "Authorization: Bearer $TOKEN"
```

### Фильтр по бесплатным событиям

```bash
curl -X GET "http://localhost:8080/v1/api/discovery/next?priceTypes=free" \
  -H "Authorization: Bearer $TOKEN"
```

### Комбинированный фильтр

```bash
curl -X GET "http://localhost:8080/v1/api/discovery/next?types=Воркшоп,Лекция&priceTypes=free,donation&places=Коворкинг" \
  -H "Authorization: Bearer $TOKEN"
```

### Фильтр по диапазону дат

```bash
curl -X GET "http://localhost:8080/v1/api/discovery/next?dateFrom=2025-12-01T00:00:00Z&dateTo=2025-12-31T23:59:59Z" \
  -H "Authorization: Bearer $TOKEN"
```

## Доступные значения

### Типы событий (`types`)

Значения зависят от данных в системе. Типичные примеры:

- `Конференция`
- `Воркшоп`
- `Лекция`
- `Встреча`
- `Вечеринка`
- `Хакатон`
- `Спорт`

### Типы цен (`priceTypes`)

- `free` — бесплатные события
- `paid` — платные события
- `donation` — события с добровольным взносом

### Места (`places`)

Поиск по подстроке (регистронезависимый). Примеры:

- `Коворкинг`
- `Офис`
- `Парк`
- `Online`
- `Zoom`

## Поведение фильтров

1. **Пустой фильтр** — возвращает все доступные события (стандартное поведение)

2. **Множественные значения** — работают как OR внутри одного параметра:
   - `types=Конференция,Воркшоп` — события типа "Конференция" ИЛИ "Воркшоп"

3. **Комбинация параметров** — работает как AND между параметрами:
   - `types=Конференция&priceTypes=free` — бесплатные конференции

4. **Регистронезависимость** — все текстовые фильтры регистронезависимы:
   - `types=конференция` эквивалентно `types=Конференция`

5. **Поиск по подстроке для мест**:
   - `places=Коворкинг` найдёт `Коворкинг "Старт"` и `Коворкинг "Центр"`

## Ответ

### Успешный ответ (200)

```json
{
  "event": {
    "id": "evt_123",
    "title": "Go Meetup",
    "description": "Встреча Go-разработчиков",
    "slot": {
      "start": "2025-12-15T18:00:00Z",
      "end": "2025-12-15T21:00:00Z"
    },
    "metadata": {
      "type": "Воркшоп",
      "place": "Коворкинг \"Старт\"",
      "priceType": "free"
    }
  },
  "conflict": false,
  "remainingPrimary": 5,
  "remainingConflicts": 0
}
```

### Очередь пуста (404)

Возвращается когда нет событий, соответствующих фильтру:

```json
{
  "error": "queue_empty",
  "message": "События для окна не найдены",
  "code": 404
}
```

### Ошибка валидации (400)

При некорректном формате даты:

```json
{
  "error": "validation_error",
  "message": "parsing time \"invalid\" as \"2006-01-02T15:04:05Z07:00\": cannot parse...",
  "code": 400
}
```

## Архитектура

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   HTTP Handler  │────▶│     Service     │────▶│     Engine      │
│ parseFilter()   │     │ NextFiltered()  │     │ ensureState()   │
└─────────────────┘     └─────────────────┘     └─────────────────┘
         │                                              │
         ▼                                              ▼
┌─────────────────┐                          ┌─────────────────┐
│ Query Params:   │                          │ Filter.Matches()│
│ - types         │                          │ для каждого     │
│ - priceTypes    │                          │ события         │
│ - places        │                          └─────────────────┘
│ - dateFrom      │
│ - dateTo        │
└─────────────────┘
```

## Производительность

- Фильтрация происходит **при построении очереди**, не при каждом запросе
- Отфильтрованные очереди **не кешируются** (каждый запрос с фильтром строит новую очередь)
- Для частого использования одинаковых фильтров рекомендуется использовать запросы без фильтров и фильтровать на клиенте
